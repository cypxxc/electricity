## 1. บทนำและวัตถุประสงค์ (Executive Summary)

ระบบติดตามและจัดการข้อมูลค่าไฟฟ้า สำนักงานเขตสุขภาพที่ 7 ถูกพัฒนาขึ้นเพื่อเปลี่ยนผ่านการจัดเก็บและวิเคราะห์ข้อมูลค่าสาธารณูปโภค (ค่าไฟฟ้า) จากรูปแบบไฟล์สเปรดชีตเดิม ให้เป็นระบบเว็บแอปพลิเคชันที่มีมาตรฐานระดับ Enterprise โดยมีเป้าหมายหลักคือ:
1. แสดงผลการวิเคราะห์และแนวโน้มการใช้จ่ายในรูปแบบแดชบอร์ดที่กระชับ ชัดเจน และอ่านง่าย
2. มีระบบจัดการข้อมูล (Admin Panel) สำหรับการเพิ่ม แก้ไข ลบ ค้นหา และตรวจสอบความถูกต้องของข้อมูล
3. จัดเก็บข้อมูลลงฐานข้อมูลเชิงสัมพันธ์จริง (PostgreSQL) โดยไม่ใช้ข้อมูลจำลอง (No Mock Data)
4. ป้องกันการบันทึกข้อมูลซ้ำซ้อน (Deduplication) ทั้งในระดับโค้ดและระดับฐานข้อมูล
5. รองรับการนำเข้าและส่งออกข้อมูลร่วมกับโปรแกรม Microsoft Excel ได้อย่างไร้รอยต่อ

## 3. การออกแบบฐานข้อมูลและการนำเข้าข้อมูลจริง (Database Design & Seed)

### 3.1 การวิเคราะห์ไฟล์ข้อมูลตั้งต้น (`สรุปค่าไฟฟ้า 62-69.xlsx`)
จากการตรวจสอบไฟล์ข้อมูลจริง พบว่าข้อมูลถูกบันทึกในรูปแบบตาราง 2 มิติ (Matrix):
- แถวแรกคือหัวเอกสาร: *"สรุปข้อมูลค่าไฟฟ้า สำนักงานเขตสุขภาพที่ 7 ปี 2562 - 2569"*
- คอลัมน์ที่ 1 คือ ปี พ.ศ. (2562 – 2569)
- คอลัมน์ที่ 2 – 13 คือ ค่าไฟฟ้ารายเดือน (ม.ค. – ธ.ค.)
- **ประวัติการบันทึกจริง:**
  - ปี 2562: เริ่มบันทึกเดือน ต.ค. – ธ.ค. (3 เดือน)
  - ปี 2563 – 2568: บันทึกครบทุกเดือน (ปีละ 12 เดือน)
  - ปี 2569: บันทึกเดือน ม.ค. – ก.ย. (9 เดือน)
  - **รวมข้อมูลจริงทั้งสิ้น:** **84 ระเบียน (Records)**

### 3.2 โครงสร้างตาราง (Database Schema)

#### ตาราง `electricity_records` (ตารางบันทึกค่าไฟฟ้า)
- `id` (Serial, Primary Key)
- `year_be` (Integer, ไม่เป็นค่าว่าง): ปี พ.ศ. เช่น 2567
- `year_ce` (Integer, ไม่เป็นค่าว่าง): ปี ค.ศ. เช่น 2024 (คำนวณจาก `year_be - 543`)
- `month` (Integer, 1 - 12, ไม่เป็นค่าว่าง): ลำดับเดือน
- `amount` (Numeric(12, 2), ไม่เป็นค่าว่าง): ยอดเงินค่าไฟฟ้า (บาท)
- `note` (Text): หมายเหตุหรือที่มาของข้อมูล
- `created_at` / `updated_at` (Timestamp with timezone): บันทึกเวลาที่สร้างและแก้ไข
- **Unique Constraint:** สร้าง Unique Index คู่กันที่ `(year_be, month)` เพื่อป้องกันไม่ให้มีข้อมูลปีและเดือนเดียวกันซ้ำในฐานข้อมูล

#### ตาราง `users` (ตารางผู้ดูแลระบบ)
- `id` (Serial, Primary Key)
- `username` (Varchar(50), Unique)
- `password_hash` (Text, เก็บรหัสผ่านที่ผ่านการ Hash ด้วย bcrypt)
- `role` (Varchar(20), ค่าเริ่มต้น `'admin'`)
- `created_at` (Timestamp)

### 3.3 การนำเข้าข้อมูลตั้งต้น (Seeding)
ระบบมีสคริปต์ `scripts/seed.ts` ที่อ่านไฟล์ `สรุปค่าไฟฟ้า 62-69.xlsx` โดยตรง แล้วแปลงข้อมูลทั้ง 84 รายการเข้าสู่ตาราง `electricity_records` พร้อมสร้างบัญชีผู้ดูแลระบบตั้งต้นชื่อ `admin`

### 4.3 ระบบป้องกันข้อมูลซ้ำซ้อน (Deduplication Validation)
ระบบมีกลไกป้องกันข้อมูลซ้ำแบบ 3 ระดับ (Defense in Depth):
1. **Client / Form Validation:** แจ้งเตือนทันทีหากป้อนข้อมูลไม่ถูกต้อง
2. **Business Service Layer:** ฟังก์ชัน `checkDuplicateRecord(yearBe, month, excludeId)` ตรวจสอบก่อนส่งคำสั่งลงฐานข้อมูล
3. **Database Constraint:** Unique Index `year_be_month_unique_idx` ในระดับ PostgreSQL บล็อกการ Insert ข้อมูลซ้ำ 100%

### 4.4 ระบบนำเข้าและส่งออกข้อมูล (Excel / CSV Integration)
- **การนำเข้า (Import):**
  - รองรับการอัปโหลดไฟล์ Excel (.xlsx) ทั้งรูปแบบตาราง 2 มิติ (Matrix) หรือตารางรายแถว (Tabular)
  - มีตัวเลือกกลยุทธ์จัดการข้อมูลซ้ำ: *"ข้ามรายการที่ซ้ำ (Skip duplicates)"* หรือ *"เขียนทับข้อมูลเดิม (Overwrite)"*
  - แสดงผลสรุปจำนวนรายการที่พบ, เพิ่มใหม่, อัปเดต และข้ามรายการที่ซ้ำ
- **การส่งออก (Export):**
  - **Excel (.xlsx):** สร้างไฟล์สมบูรณ์แบบ 2 ชีต (ชีตตารางแจกแจงรายเดือน 2 มิติ + ชีตรายการทั้งหมด)
  - **CSV (.csv):** เข้ารหัสด้วย **UTF-8 BOM (`\uFEFF`)** ทำให้เปิดอ่านใน Microsoft Excel บน Windows ได้ทันทีโดยภาษาไทยไม่เพี้ยนเป็นเครื่องหมายคำถามหรืออักขระแปลกปลอม

## 5. การปรับปรุงเลย์เอาต์ (Dense & Balanced Enterprise Layout)

เพื่อให้ผู้บริหารและเจ้าหน้าที่สามารถดูข้อมูลสำคัญได้ครบถ้วนโดยไม่ต้องเลื่อนหน้าจอบ่อย ได้ปรับโครงสร้าง UI ดังนี้:
- **Responsive Wide Container (`max-w-[1640px]`):** ขยายการแสดงผลเต็มพื้นที่หน้าจอเดสก์ท็อปอย่างสมดุล จัดกึ่งกลางจออย่างลงตัว
- **ลดช่องว่างแนวตั้ง (Reduce Whitespace):** ลด Padding และ Gap เพื่อให้ข้อมูลการ์ด KPI, กราฟทั้ง 2 ชุด และตารางแจกแจง ปรากฏในระยะสายตา (Above the fold) ได้อย่างสบายตา
- **Compact Sizing:** รักษาขนาดฟอนต์และองค์ประกอบให้กะทัดรัด คมชัด ไม่ขยายตัวอักษรหรือการ์ดใหญ่จนดูเทอะทะ

## 7. คู่มือการติดตั้งและเริ่มต้นใช้งาน (Operations & Deployment Guide)

### 7.1 ความต้องการขั้นต่ำของระบบ (Prerequisites)
- Docker Desktop
- Bun Runtime (v1.3 ขึ้นไป)

### 7.2 คำสั่งเริ่มต้นระบบ (Quick Start)

```bash
# 1. เริ่มต้นฐานข้อมูล PostgreSQL ผ่าน Docker
docker compose up -d

# 2. ปรับใช้ Database Schema (หากรันเป็นครั้งแรก)
bun run db:push

# 3. นำเข้าข้อมูลประวัติจาก Excel เข้าสู่ฐานข้อมูล
bun run seed

# 4. เริ่มต้น Development Server
bun run dev
```

### 7.3 ข้อมูลบัญชีผู้ดูแลระบบ (Default Credentials)
- **URL เข้าสู่ระบบ:** `http://localhost:3000/login`
- **ชื่อผู้ใช้งาน (Username):** `admin`
- **รหัสผ่าน (Password):** `adminpassword123`

### 7.4 แผนผังเส้นทาง URL ของระบบ (Route Map)
- `/` : หน้าแดชบอร์ดภาพรวมการใช้จ่ายค่าไฟฟ้า
- `/login` : หน้าเข้าสู่ระบบสำหรับเจ้าหน้าที่ผู้ดูแลระบบ
- `/admin` : หน้าจัดการฐานข้อมูลค่าไฟฟ้า (เพิ่ม, แก้ไข, ลบ, ค้นหา)
- `/api/export?format=xlsx` : ลิงก์ดาวน์โหลดรายงานรูปแบบ Excel (.xlsx)
- `/api/export?format=csv` : ลิงก์ดาวน์โหลดรายงานรูปแบบ CSV (.csv)
- `/api/import` : จุดรับการอัปโหลดไฟล์นำเข้าข้อมูล (.xlsx)

## 8. สรุปผลสัมฤทธิ์ของโครงการ

ระบบติดตามและจัดการข้อมูลค่าไฟฟ้า สำนักงานเขตสุขภาพที่ 7 ได้รับการพัฒนาเสร็จสิ้นตรงตามข้อกำหนดทางเทคนิคและหลักการออกแบบที่ตั้งไว้ทุกประการ ข้อมูลทั้งหมดถูกจัดเก็บลงฐานข้อมูลจริงอย่างถูกต้อง ปลอดภัย และพร้อมสำหรับการใช้งานจริงหรือต่อยอดในอนาคตครับ
